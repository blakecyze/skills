Design and integration

The Skill

Turning the catalogue and the craft into a working Claude Code skill: how it should behave, what takes precedence, and where an optional Codex generator fits without becoming a liability.

A skill, not a prompt. It plugs into the kanso suite, exposes a slash command, and treats the humanisation guidelines as load-bearing. The model that writes the words is the least important part, which is the central design call below.

01

Naming

The thing you were reaching for is a machine that imitates a person. A few candidates, with the command each would expose:

mimicPlain and direct. The act of imitation itself. /mimic reads oddly as a verb for "clean this up", though.
mimesisRecommended. Greek for imitation or representation. Short, brandable, sits naturally beside kanso, and fits your aesthetic. Name it after what it neutralises. /mimesis or keep /humanise as the verb-command and "mimesis" as the suite name.
turingThe imitation game. Clear lineage, but heavy and a touch obvious.
turkFrom the Mechanical Turk, the automaton that hid a human. Literally a machine passing as a person. Witty, slightly obscure.
uncannyThe valley of almost-human. Evocative, but names the symptom, not the act.

My pick is mimesis for the suite identity, keeping /humanise as the command verb so the action stays obvious at the call site. If you want one word doing both, /mimesis works.

02

Three modes

The skill should detect intent and run one of three modes, mirroring how kanso-audit and kanso-refactor split read-only analysis from edits.

audit

Read-only. Flags every tell in supplied text with location and category, scored by severity. The diagnostic pass. No rewriting.

rewrite

Meaning-preserving humanisation of an existing draft. Applies the craft principles and the final pass. Never changes factual claims, never invents experience.

generate

Drafts new text already humanised from the start, rather than producing clean-then-clean output.

03

The precedence stack

This is the architectural spine. The guidelines outrank the model. Layers run top to bottom, and the lower a layer sits, the more optional and replaceable it is.

L1Guideline corpus. The distilled tells and craft (docs 01 and 02) shipped as reference markdown the skill reads on every run. Primary. Model-independent. Never skipped.
L2Deterministic linter. A scripted pass: regex and word-list checks for em dashes, smart quotes, the blacklist, and "not X but Y" shapes. Runs regardless of which model wrote the text, so the output is safe even if generation went sideways.
L3Generator (optional). Whatever model is to hand. Claude by default. Codex / GPT-5.5 only if installed and opted into. The generator is the last and most swappable layer, never the thing the quality rests on.

The point: even if a future model regresses or a generator misbehaves, L1 and L2 still produce humanised, em-dash-free text. Quality is a property of the guidelines and the linter, not of the model.

04

The Codex / GPT-5.5 option

You asked the skill to detect the Codex CLI and route generation to GPT-5.5 because it is "better". GPT-5.5 is real, released April 2026, and Codex CLI does run on it, so the plumbing is feasible: probe for codex on PATH, and if present and the user opts in, shell out for the generate step.

Flagged: the "better" premise

The research cuts against routing prose to GPT on a quality assumption. The GPT lineage is the origin of most documented tells, the em dash, "delve", negative parallelism, and 5.5 is tuned for agentic coding and tool use, not prose voice. There is no evidence it humanises better than the model already running the skill.

Proposed alternative, which the stack already encodes: keep generation model-agnostic, make Codex strictly optional, and always run the same L1 guidelines and L2 linter pass afterwards no matter who generated. So if Codex writes the draft, the Claude-run humanise pass still cleans it. You get the option without betting quality on it.

If you do want the option live, gate it behind an explicit flag (--gen codex) rather than auto-routing, so the default path stays predictable.

05

Two absolute rules

— Zero em dashes, ever. The linter strips and restructures them into commas, full stops or parentheses. It also catches the spaced-hyphen and en-dash-as-em workarounds.

Catch the merely perceived, too. The skill flags constructions that read as AI even when grammatically fine: tricolons, "it's not X it's Y", participle tails, dutiful sign-offs. These get downgraded or rewritten, not waved through on a technicality.

06

Shape on disk

Mirror the existing kanso skills so it feels native to the suite.

mimesis/ ├─ SKILL.md description, triggers, the three modes ├─ reference/ │ ├─ tells.md distilled from doc 01, versioned by model era │ └─ craft.md distilled from doc 02, the final-pass checklist ├─ linter deterministic em-dash + blacklist + pattern pass └─ codex.md optional generator: detection + opt-in gate

The SKILL.md description must trigger on the right asks: "make this sound human", "humanise this", "does this read as AI", "remove AI tells", "de-slop this". Triggering accuracy is its own piece of work, the same way your kanso descriptions are tuned.

07

Limits worth stating in the skill

  • Detectors false-positive. The skill writes for signal and voice, it does not promise to beat any given detector.
  • Meaning preservation is mandatory in rewrite mode. No claim changes, no fabricated anecdotes.
  • The kill list is versioned, not eternal. Plan to revisit it as models drift.
