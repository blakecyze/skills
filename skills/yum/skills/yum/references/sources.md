# Source router

Choose by the decision to make. These destinations are starting points, not evidence that a particular product or screen is present. Descriptions were reviewed in September 2026; confirm current access, filters, and coverage when searching. Pricing, library counts, and connector entitlements are deliberately omitted.

## Production interfaces

| Source | Choose for | Search and inspect |
|---|---|---|
| [Mobbin](https://mobbin.com/) | Mobile and web product screens and flows | Start with the task or UI element, then platform/category. Capture the actual app, state, and flow identity |
| [Refero](https://refero.design/) | Product screens, flows, and visual comparison | Search the task, then inspect the returned material; a search shell without loaded screens is not a visual reference |
| [Nicelydone](https://nicelydone.club/) | Web app dashboards, settings, admin, and other SaaS surfaces | Start with page type or a visible label; distinguish product UI from its public marketing page |
| [Page Flows](https://pageflows.com/) | Journey order, decisions, and transitions | Inspect recordings for the relevant task and platform; note where the observed sequence starts and stops |

For settings, billing, and admin, start with product references. Award galleries can supply an aesthetic direction but do not establish how those tasks work.

## on.design: signed-in-only check

When visual inspiration is relevant, open [on.design](https://on.design/) in the available existing browser session and start with **Popular**, the requested default homepage view. Use that URL directly; do not invent a `/popular` route or alternate sort parameters. If the visible selection differs, select Popular through the UI.

If the page redirects to sign-in, shows a login gate, or signed-in access cannot be established, skip this source and continue elsewhere. Do not initiate sign-in, request credentials, ask the user to authenticate, or retry through another browser merely to gain access. A signed-out session is an expected skip, not a blocked research task.

When signed in, inspect relevant items and cite their actual links and creators when available. Popularity is a discovery signal, not evidence of usability or product performance. Treat items as inspiration unless their shipped context is verified. Never describe unseen content from the login page.

## Query construction

Use the dimensions the source actually exposes. These are query ideas, not promises that every library has named filters:

- **App task:** platform + user action + relevant state, such as web / change plan / payment failure.
- **Marketing:** product category + communication problem, such as developer tool / interactive demo / pricing explanation.
- **Visual detail:** surface + dimension, such as footer / contact hierarchy or OG image / short headline and product crop.
- **Component:** common naming variants, such as dialog/modal, then official documentation.

## Access fallback

Use a connected tool when it provides relevant results; otherwise use permitted browser access or supplied captures. Do not assume an MCP connection exists because a vendor advertises one. Public metadata can support discovery while the screens themselves remain inaccessible.

If a source is blocked, use another relevant source or a live product. Preserve the original source as an uninspected lead only when useful. Do not turn access failures into fabricated findings, repeat identical blocked requests, or claim the library is empty.
