# Comparison lenses

Read only the matching surface. The goal is a design decision, not a mandatory report for every dimension.

| Surface | Compare | Evidence limit |
|---|---|---|
| Onboarding or paywall | First useful action, step order, defer/skip, account and permission timing, price disclosure, restore and recovery paths | A partial recording cannot establish the complete journey; platform prompts and experiment variants may differ |
| Settings, admin, dashboard | Navigation grouping, density, role permissions, defaults, save model, pending/error/empty states | Missing access or screenshots cannot prove an option is absent |
| Landing page | Value claim, section order, proof type and placement, CTA destinations, pricing context | Gallery captures do not show current interactions or conversion performance |
| Portfolio | Work index, case narrative, evidence of contribution and outcome, contact path | A visual case study is not proof of the creator's role or reported results |
| Footer | Link taxonomy, legal/contact roles, repeated CTA, hierarchy | A crop may omit surrounding page context and mobile behaviour |
| OG or social image | Focal point, crop, type hierarchy, readability at preview size | Gallery art may differ from current metadata; identify the source site |
| Typography | Display/text/data roles, pairing, weight contrast, reading density | Name fonts only from source metadata or inspected styles; exact measurements need evidence |
| Motion | Trigger, moving object, continuity, interruption, endpoint | A still cannot establish choreography; durations require measurement; reduced-motion behaviour needs its own observation |
| Design-system component | Anatomy, naming, states, focus and keyboard contract, documented API | Visit official system docs; screenshots and kits do not establish APIs or accessibility |

## Evidence notes

A useful note has an identity and a bounded claim:

`product / item URL or supplied file / platform / state / capture date or unknown / inspection date / observed detail`

Keep date of inspection separate from age of the capture. Multiple captures of the same product are not independent peers. For a still, describe what is visible; for a recording, record the observed span and gaps.

## Synthesis example

Suppose two supplied flows show guest browsing before account creation and a third starts with sign-in. The observed pattern is delayed authentication in two samples. Reduced initial effort is an inference. Recommending guest browsing depends on whether the target can deliver useful value without an account. Neither frequency nor visual polish proves that the pattern converts better.

## Comparison quality

Prefer a peer that solves the same task under similar constraints to a famous product from a different category. Seek a counterexample when it could change the recommendation, not to fill a report template. Preserve disagreement where platform, audience, or business model explains it.
