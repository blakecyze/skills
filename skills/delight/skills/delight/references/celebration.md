# Milestone celebrations

Distinguish routine confirmation from a milestone crossing. Match intensity to significance and repetition: local confirmation for repeatable work, brief emphasis for meaningful completion, a more expressive sequence for a rare achievement when the product supports it. Do not invent milestones to justify effects.

Define the authoritative success source, milestone condition, replay policy, dismissal, final state, and reduced-motion equivalent. A click, optimistic update, or animation ending does not establish success.

Use an existing event identity or transition when duplicate delivery is possible. Ordinary rerenders must not replay a one-time milestone. Choose session or persistent suppression according to the product requirement; do not add a backend merely to suppress a local flourish. Suppress decoration, never the underlying result or accessible status.

Decorative overlays must not intercept input or steal focus. A full-screen sequence needs an available continue or dismiss action; animation completion must not unlock essential actions. Sharing stays optional.

Read [scenarios.md](scenarios.md) for completion rituals, character reactions, confetti, and replay edge cases. Exercise applicable failure, duplicate delivery, revisit, navigation, and rapid-success scenarios. Verify integration with the real success event separately from a visual preview.
